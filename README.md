# صفحه‌ی لیست موزیک (Teodel) — فرانت‌اند

Laravel Blade + Tailwind CSS 3 + jQuery. دو زبانه (فارسی RTL / انگلیسی LTR)، موبایل‌محور و هم‌وزن برای دسکتاپ.
فقط فرانت است؛ هر جا داده یا ارسال لازم است یک نقطه‌ی اتصال خالی گذاشته شده.

## نصب در پروژه‌ی لاراول

```bash
npm i -D tailwindcss@3 postcss autoprefixer
npm i jquery html2canvas
```

فونت‌ها با npm نصب نمی‌شوند؛ فایل‌هایشان را در `public/fonts` بگذارید (راهنما: `public/fonts/README.txt`).

1. پوشه‌های `resources/`, `lang/`, `app/Support/`, `public/images/` را در پروژه کپی کنید.
   `tailwind.config.js`, `postcss.config.js`, `vite.config.js` را با فایل‌های موجود ادغام کنید.
2. در `composer.json` زیر `autoload.files` اضافه کنید: `"app/Support/helpers.php"` و بعد `composer dump-autoload`
   (تابع `num()` اعداد را در زبان فارسی فارسی‌نویس می‌کند).
3. محتوای `routes/music.php` را در `routes/web.php` بگذارید. `MusicController` فعلاً داده‌ی نمونه دارد.
4. `npm run dev` / `npm run build`.

## تغییرات شخصی: CSS، رنگ و فونت

- **هر تغییر دلخواه:** فقط `resources/css/custom.css` را ویرایش کنید (آخر از همه لود می‌شود، پس برنده است).
- **رنگ اصلی سایت:** متغیرهای `--brand-*` همان فایل (سه عدد قرمز، سبز، آبی).
- **فونت:** فایل‌ها در `public/fonts`، تعریف آن‌ها در `resources/css/fonts.css`، و انتخاب فونت هر زبان با `--font-fa` و `--font-en` در `custom.css`.
  فارسی: یکان بخ (`YekanBakh-Regular/Bold/Heavy.woff2`) | انگلیسی: Funnel Display (`FunnelDisplay-Variable.woff2` یا `.ttf`).

## صفحه‌ی آموزش (مراحل ۱ تا ۸) — تک‌صفحه‌ای

- مسیرها: `/music/{id}` (می‌رود به مرحله‌ی فعلی) و `/music/{id}/step/{n}` (لینک مستقیم هر مرحله).
- صفحه: `resources/views/music/lesson.blade.php`. **محتوای هر ۸ مرحله با `@include` داخل همین صفحه می‌آید**
  و تعویض مرحله با `resources/js/modules/lesson.js` بدون رفرش انجام می‌شود (آدرس با history عوض می‌شود، Back/Forward کار می‌کند).
- **هر مرحله فایل جدا دارد:** `resources/views/music/steps/{play,lyrics,words,listening,shadowing,karaoke,repeat,details}.blade.php`.
  هر مرحله که ساخته می‌شود، فقط همان فایل را پر کنید.
- چون همه‌ی مرحله‌ها هم‌زمان در صفحه‌اند: `id` های داخل هر مرحله را با نام مرحله شروع کنید (مثلاً `lyrics-list`)،
  و کارهای سنگین (پخش صدا/ویدیو) را فقط هنگام فعال‌شدن مرحله‌ی خودش شروع کنید:

```js
$(document).on('lesson:step-change', (e, { step, key }) => {
    if (key === 'lyrics') { /* شروع کن */ } else { /* متوقف کن */ }
});
```

- کاربر رایگان روی آهنگ‌های غیررایگان فقط `free_steps` مرحله‌ی اول را می‌بیند؛ مرحله‌های قفل به‌جای محتوای واقعی
  `steps/_locked.blade.php` را می‌گیرند (محتوای پولی داخل HTML نمی‌آید).
- متن‌ها: `lang/{fa,en}/lesson.php` (توضیح هر مرحله فعلاً موقت است، به‌جز مرحله‌ی lyrics).

## مرحله‌ی ۱ (play) و ۷ (repeat)

- هر دو از یک ساختار مشترک می‌آیند: `steps/_listen-rate.blade.php` = پخش‌کننده (`x-lesson.player`) + امتیازدهی ۱ تا ۱۰ (`x-lesson.rating`). فقط متن پرسش (`lang/*/lesson.php` ← `rate.play` و `rate.repeat`) فرق دارد.
- امتیاز با شنیدن آزاد می‌شود: کاربر باید حدود ۹۰٪ ثانیه‌های موزیک را **واقعاً پخش‌شده** بشنود (پرش با نوار زمان حساب نمی‌شود). تا آن موقع اعداد قفل‌اند.
- پیشرفت مرحله: تا ۸۰٪ با شنیدن، ۱۰۰٪ با ثبت امتیاز.
- مرحله‌ی ۷ بعد از ثبت، امتیاز «اول» و «حالا» را کنار هم و با پیام پیشرفت نشان می‌دهد.
- 🔌 بک‌اند: `$song['audio']` (آدرس صوت؛ خالی = حالت دمو)، `$song['play_score']` و `$song['repeat_score']` (۱ تا ۱۰ یا null).
  ثبت امتیاز: `$(document).on('lesson:rating', (e, { song, kind, score, baseline }) => {...})`.
  تا وصل‌شدن بک‌اند امتیاز مرحله‌ی اول در مرورگر نگه داشته می‌شود (`LOCAL_SCORES` در `rating.js`؛ بعد از اتصال `false` کنید).
- 🔌 `$song['vocals']` = بخش‌هایی که خواننده می‌خواند، `[[شروع، پایان], ...]` به ثانیه (بک‌اند می‌تواند از زمان‌بندی لیریک بسازد). روی نوار با نقطه‌ی کوچک و پررنگ‌تر شدن همان بخش نشان داده می‌شود؛ خالی = نمایش داده نمی‌شود.
- پرش روی نوار: اگر سرور فایل صوتی «Range request» را پشتیبانی نکند (مثل `php artisan serve`)، پخش‌کننده خودش فایل را یک‌بار کامل می‌گیرد تا پرش درست کار کند. روی سرور واقعی (Nginx/Apache/CDN) خودبه‌خود پشتیبانی می‌شود. فایل از دامنه‌ی دیگر باید CORS داشته باشد.
- تصویر اختیاری کنار امتیازدهی (دسکتاپ): `public/images/lesson/mascot.webp`.

## مرحله‌ی ۲ (lyrics)

- فایل‌ها: `steps/lyrics.blade.php` (پخش‌کننده + لیریک)، `x-lesson.lyrics`، `resources/js/modules/lyrics.js`، `app/Support/Lrc.php`.
- موزیک دوباره پخش می‌شود و لیریک هم‌زمان می‌آید: خط جاری برجسته می‌شود و کلمه‌ها یکی‌یکی رنگ می‌گیرند، خط‌های گذشته کم‌رنگ‌اند و در بخش بی‌کلام هیچ خطی برجسته نیست.
  کلیک روی هر خط، موزیک را از همان‌جا پخش می‌کند. اسکرول روی خط جاری خودکار است (کاربر اسکرول کند، خاموش می‌شود و دکمه‌ی «خط جاری» می‌آید).
- مرحله بعد از شنیدن حدود ۹۰٪ موزیک تمام می‌شود (مثل پیشرفت زنده‌ی بقیه‌ی مرحله‌ها).
- 🔌 بک‌اند: `$song['lyrics']` = رشته‌ی LRC (`[00:21.53]Mm` ...) **یا** آرایه‌ی `[['t' => 21.53, 'text' => '...', 'tr' => 'ترجمه (اختیاری)']]`.
  اگر `tr` بدهید، دکمه‌ی «ترجمه» خودکار ظاهر می‌شود. اگر `lyrics` نرسد، لیریک نمونه برای تست نشان داده می‌شود.
- نشانه‌ی «جاهایی که خواننده می‌خواند» روی نوار مرحله‌های ۱، ۲ و ۷ حالا از همین زمان‌بندی لیریک ساخته می‌شود (اگر لیریک نبود، از `$song['vocals']`).
- زمان کل موزیک (`$song['duration']`) باید درست باشد تا نشانه‌ها قبل از اولین پخش هم سر جای خودشان باشند.

## مرحله‌ی ۳ (words)

- فایل‌ها: `steps/words.blade.php` ← `x-lesson.words`، `resources/js/modules/words.js`، `app/Support/Words.php`.
- موزیک پخش نمی‌شود؛ فقط لیریک دیده می‌شود. لغت‌های انتخاب پشتیبان زرد هایلایت‌اند؛ کلیک روی آن‌ها (یا روی **هر کلمه‌ی دیگر**) کارت توضیحات را باز می‌کند
  (دسکتاپ: کارت کنار لیریک | موبایل/تبلت: Bottom Sheet).
- کارت: عبارت و نوع، تلفظ UK/US (فایل صوتی پشتیبان یا، اگر نبود، صدای مرورگر)، جمله‌ی موزیک، توضیح کامل، سطح، مترادف، متضاد و **ترجمه‌ی تار** (با کلیک نمایش داده می‌شود و با لغت بعدی دوباره تار می‌شود).
  دکمه‌ی بوکمارک روی کارت است و لغت‌های ذخیره‌شده داخل لیریک خط‌زیر می‌گیرند. «لغت قبل/بعد» بین لغت‌های پشتیبان می‌چرخد.
- مرحله وقتی تمام می‌شود که کاربر همه‌ی لغت‌های پشتیبان را دیده باشد.
- 🔌 بک‌اند:
  - `$song['words']` = لغت‌های دشوار (شکل کامل در توضیح بالای `app/Support/Words.php`: `phrase, type, level, ipa{uk,us}, audio{uk,us}, meaning, synonyms[], antonyms[], translate`).
    اگر نرسد، چند لغت نمونه‌ی موزیک تست نشان داده می‌شود.
  - `$song['saved_words']` = کلیدهای (حروف کوچک) بوکمارک‌شده‌ی قبلی کاربر.
  - ذخیره‌ی بوکمارک: `$(document).on('word:bookmark', (e, { song, key, text, saved, line }) => {...})`.
    تا وصل‌شدن بک‌اند در مرورگر نگه داشته می‌شود (`LOCAL_SAVE` در `words.js`؛ بعد از اتصال `false` کنید). لیست «لغات ذخیره‌شده» بعداً از همین داده ساخته می‌شود.
  - کلمه‌ی دلخواه کاربر: `$song['lookup_url']` (GET `?word=...` ← JSON هم‌شکل یک لغت، یا `null` اگر چیزی نبود) **یا** `Teodel.words.lookup = async (word, { song, line }) => ({...})`.
    اگر اطلاعاتی نباشد، پیام «توضیحی ثبت نشده» و لینک دیکشنری (`/dictionary?q=...`) نشان داده می‌شود و کاربر باز هم می‌تواند آن را ذخیره کند.

## مرحله‌ی ۴ (listening)

- فایل‌ها: `steps/listening.blade.php` ← `x-lesson.clip`، `resources/js/modules/{clip,listening}.js`، `app/Support/Listening.php`.
- دو بخش: **آسان** (یک کلمه‌ی خالی) و **سخت** (یک عبارت؛ هر کلمه یک کادر، با Space به کادر بعد می‌رود و چسباندن عبارت بین کادرها پخش می‌شود).
- هر تمرین یک کلیپ کوچک دارد که فقط همان بخش از موزیک را پخش می‌کند (سرعت ۰٫۵ تا ۱٫۵). همه‌ی کلیپ‌ها یک فایل صوتی مشترک دارند و هم‌زمان فقط یکی پخش می‌شود.
- بعد از ۲ جواب غلط دکمه‌ی «نمایش جواب» می‌آید. تمرینِ «جواب‌دیده» تمام‌شده حساب می‌شود ولی «درست» نه. نتیجه در مرورگر می‌ماند (`LOCAL_SAVE` در `listening.js`).
- مرحله وقتی تمام می‌شود که همه‌ی تمرین‌ها تمام شده باشند؛ در پایان خلاصه‌ی «چند تا از چند تا» نشان داده می‌شود.
- 🔌 بک‌اند:
  - `$song['listening']` = `[ ['start'=>12.5, 'end'=>16, 'text'=>'…the whole line…', 'answer'=>'run'], … ]` (برای آسان یک کلمه، برای سخت یک عبارت؛ در `Listening.php` توضیح کامل‌تر). اگر نرسد، از لیریک نمونه ساخته می‌شود.
  - بررسی جواب: پیش‌فرض در مرورگر است (جواب‌ها داخل `data-answers` هستند). برای بررسی سمت سرور: `Teodel.listening.check = async ({song,id,mode,answers}, values) => [true,false,…]`.
  - نتیجه: `$(document).on('listening:result', (e, { song, id, mode, correct, attempts, revealed }) => {...})`.

## مرحله‌ی ۵ (shadowing)

- فایل‌ها: `steps/shadowing.blade.php` ← `x-lesson.clip` (با `:turn="true"`)، `resources/js/modules/{clip,shadowing}.js`، `app/Support/Shadowing.php`.
- هر بخش یک کلیپ کوچک است. بعد از پخش، **«نوبت توست»** شروع می‌شود: نوار (به‌اندازه‌ی بخش + ۱ ثانیه، با سرعت انتخاب‌شده) پر می‌شود و کاربر بلند تکرار می‌کند.
  وقتی نوبت تمام شد (یا «تکرار کردم» را زد) یک نقطه‌ی تکرار پر می‌شود. اگر وسط نوبت دکمه‌ی پخش را بزند، بخش دوباره از اول پخش می‌شود و آن دور حساب نمی‌شود.
- متن هر بخش تار است و با کلیک نشان داده می‌شود (دوباره کلیک = تار).
- هدف پیش‌فرض ۳ تکرار برای هر بخش است؛ تکرار بیشتر هم شمرده می‌شود. مرحله وقتی تمام می‌شود که همه‌ی بخش‌ها به هدف برسند.
- برنامه صدای کاربر را نمی‌شنود (نیازی به میکروفون نیست)؛ «تکرار» یعنی نوبت کاربر تا آخر ادامه پیدا کرده است.
- 🔌 بک‌اند:
  - `$song['shadowing'] = [ ['start'=>24.4, 'end'=>30.6, 'text'=>"خط ۱\nخط ۲"], … ]` و اختیاری `$song['shadowing_repeats']` (پیش‌فرض ۳). اگر نرسد، بخش‌های نمونه از لیریک ساخته می‌شود.
  - رویداد: `$(document).on('shadowing:round', (e, { song, id, rounds, target, done, revealed }) => {...})` برای ذخیره‌ی هر دور.
  - تا وصل‌شدن بک‌اند نتیجه در مرورگر می‌ماند (`LOCAL_SAVE` در `shadowing.js`).

## مرحله‌ی ۶ (karaoke)

- فایل‌ها: `steps/karaoke.blade.php`، `x-lesson.player` (با `kind="karaoke"`)، `resources/js/modules/{karaoke,player}.js`.
- موزیک کامل پخش می‌شود و لیریک **کلمه‌به‌کلمه** با خواننده جلو می‌رود (خط جاری بزرگ، خط بعدی کم‌رنگ). بین خط‌ها شمارش معکوس «آماده شو» یا «بخش بی‌کلام» نشان داده می‌شود.
  بخش‌هایی که خواننده می‌خواند روی نوار پیشرفت علامت دارند (مثل مرحله‌ی ۲).
- **میکسر** زیر پخش‌کننده: اسلایدر و دکمه‌ی بی‌صدای جدا برای «صدای خواننده» و «صدای موزیک» + دکمه‌ی بزرگ «خواننده را حذف کن؛ خودم می‌خوانم». مقدارها در `localStorage` (`teodel:mixer`) می‌مانند.
- مرحله وقتی تمام می‌شود که کاربر حدود ۹۰٪ موزیک را شنیده باشد (مثل مرحله‌ی ۲).
- 🔌 بک‌اند — **دو فایل صوتیِ هم‌طول** لازم است (جداکردن صدا در مرورگر ممکن نیست):
  - `$song['audio_vocal']` = فقط صدای خواننده، `$song['audio_backing']` = موزیک بدون خواننده. با هر دو، دو اسلایدر مستقل کار می‌کنند و دو فایل با هم هم‌زمان می‌مانند (اختلاف بیشتر از ۰٫۲۵ ثانیه خودکار اصلاح می‌شود).
  - اگر فقط `$song['audio']` باشد: فقط «صدای موزیک» (= بلندی کل) کار می‌کند، حذف خواننده غیرفعال است و یک توضیح نشان داده می‌شود.
  - بدون فایل (حالت دمو): همه‌چیز کار می‌کند ولی صدایی نیست.
  - فایل‌ها باید Range request را پشتیبانی کنند (مثل بقیه‌ی مرحله‌ها)؛ در iOS کنترل صدا از WebAudio انجام می‌شود که فایل باید هم‌دامنه یا دارای CORS باشد.

## مرحله‌ی ۸ (details)

- فایل‌ها: `steps/details.blade.php`، `app/Support/Details.php`، `resources/js/modules/details.js`.
- بالا: کاور، نام موزیک، خواننده و ۸ مشخصه (سطح، لهجه، لغت بر دقیقه، موضوع، سال انتشار، زمان، ژانر، نام آلبوم)؛ مشخصه‌ی خالی «نامشخص» نشان داده می‌شود.
  بعد: **تفسیر موزیک** و **توضیحات** (کارت‌های آرایه‌ی ادبی و نکته‌ی زبان انگلیسی، هرکدام با مثالی از خودِ آهنگ).
- مرحله وقتی تمام می‌شود که کاربر به انتهای صفحه رسیده و حداقل ۴ ثانیه آنجا مانده باشد (با اسکرول سریع تمام‌شده حساب نمی‌شود).
- 🔌 بک‌اند:
  - مشخصه‌ها از همان فیلدهای کارت موزیک: `cover, title, artist, level, accent, wpm, topic, year, duration, genre, album` (بدون فیلد جدید).
  - `$song['interpretation']` = رشته (پاراگراف‌ها با یک خط خالی) یا آرایه‌ی پاراگراف‌ها.
  - `$song['notes']` = `[ ['title' => 'آرایه‌های ادبی', 'type' => 'literary', 'items' => [ ['term' => 'استعاره', 'example' => 'Little sparks in a grand design', 'text' => 'توضیح'] ]], ['title' => 'نکته‌های زبان', 'type' => 'language', 'items' => [...]] ]`
    (یا فقط یک رشته‌ی ساده). همه‌ی متن‌ها escape می‌شوند. اگر چیزی نرسد، متن نمونه نشان داده می‌شود.

## صفحه‌ی لغات و عبارت‌های هایلایت‌شده (`/words`)

- فایل‌ها: `WordsController`، `words/index.blade.php`، `app/Support/SavedWords.php`، `resources/js/modules/saved-words.js`، `lang/{fa,en}/words.php`، مسیر `words.index` در `routes/music.php`.
- **لیست:** کارت‌ها با تصویر، لغت، نوع، تلفظ (دکمه‌ی پخش)، تعریف و دکمه‌ی «اطلاعات بیشتر». جست‌وجو (لغت، ترجمه، تعریف)، فیلتر وضعیت (مرور نشده / در حال یادگیری / یاد گرفته‌ام)،
  مرتب‌سازی (جدیدترین، قدیمی‌ترین، الفبا، سطح) و تب‌های سطح A1 تا C1 با شمارنده؛ همه بدون رفرش. «نمایش بیشتر» بعد از ۱۲ مورد.
- **حذف:** بوکمارک روی کارت لغت را بلافاصله حذف می‌کند و ۶ ثانیه «بازگردانی» نشان می‌دهد (اشتباه کلیک‌شدن بی‌ضرر است).
- **دیالوگ اطلاعات = offcanvas** (کشوی تمام‌قد از سمت «پایان»: در فارسی چپ، در انگلیسی راست؛ روی موبایل تمام‌عرض). فقط بدنه اسکرول می‌خورد و نوار پایین ثابت است.

## تیکت‌ها (`/tickets`)

لیست تیکت‌های کاربر با وضعیت، ساخت تیکت جدید برای پشتیبانی و مدیریت تیکت‌های باز. همه در یک صفحه و بدون رفرش. دسکتاپ دو ستونه (لیست | گفتگو)؛ موبایل: لیست ← گفتگو یا فرم با دکمه‌ی برگشت (برگشت مرورگر هم کار می‌کند و در گفتگو/فرم نوار پایین موبایل مخفی می‌شود تا جا برای جواب‌دادن باشد).

- **وضعیت‌ها:** `open` (در انتظار پشتیبانی)، `answered` (پشتیبانی جواب داده؛ نوبت کاربر)، `closed`. کارت‌های بالای صفحه و چیپ‌ها فیلتر می‌کنند؛ جست‌وجو روی موضوع و کد تیکت. پاسخ ندیده‌ی پشتیبانی با نقطه و «پاسخ تازه» مشخص می‌شود (`unread`).
- **تیکت جدید:** بخش (فنی، پرداخت و اشتراک، محتوای آموزشی، حساب کاربری، پیشنهاد)، موضوع (۳ تا ۱۲۰)، توضیح (۱۰ تا ۳۰۰۰) و تا ۳ عکس (JPG/PNG/WebP، هرکدام تا ۲ مگابایت). اعتبارسنجی فرانت فقط برای راحتی کاربر است؛ سرور دوباره بررسی کند.
- **مدیریت:** جواب‌دادن (با عکس، Ctrl+Enter)، **بستن** (با تأیید) و **بازکردن دوباره**. در تیکت بسته، جواب‌دادن بسته است و فقط «بازکردن دوباره» دارد. جواب کاربر وضعیت را به `open` برمی‌گرداند.
- تاریخ‌ها در فارسی شمسی (Intl) و زمان نسبی («۲ ساعت پیش») نمایش داده می‌شوند.

**🔌 بک‌اند** (قرارداد کامل بالای `app/Support/Tickets.php`):
1. داده: `$tickets` = `[ { id, code, subject, dept, status, unread, created_at, updated_at, messages?: [ { id, from: user|support, name?, text, at, files:[{name,url}] } ] } ]`. اگر `messages` را در لیست ندهید، با `data-detail-url` هنگام باز کردن هر تیکت می‌آید.
2. دو راه اتصال: (الف) `$urls` را در کنترلر بدهید (`detail`، `create`، `reply`، `close`، `reopen`؛ جای شناسه `__ID__`) تا فرانت خودش POST/GET چندبخشی با CSRF بزند؛ (ب) یا `Teodel.tickets.api.create/reply/close/reopen/detail/read` را جایگزین کنید (هرکدام Promise).
3. خطای اعتبارسنجی: HTTP 422 با `{ errors: { subject: ['…'] } }` زیر همان فیلد نشان داده می‌شود.
4. رویدادها بعد از موفقیت: `ticket:created`، `ticket:replied`، `ticket:closed`، `ticket:reopened`، `ticket:read` (`(e, { ticket })`).
5. `LOCAL = true` در `tickets.js`: تیکت‌ها (بدون عکس‌ها) در localStorage می‌مانند. با اتصال بک‌اند `false` کنید.
6. لینک «پشتیبانی/تیکت» در `Nav::items()` را به `url('/tickets')` بدهید.

## آزمون تعیین سطح (`/level-test`)

سه آزمون جدا: **دایره واژگان**، **گرامر و دستور زبان**، **درک شنیداری** (خواندن و صحبت‌کردن فعلاً نیست، چون سیستم تصحیحش نداریم). همه در یک صفحه و بدون رفرش: معرفی ← انتخاب آزمون ← آزمون ← نتیجه و مرور (دکمه‌ی «برگشت» مرورگر هم کار می‌کند؛ وسط آزمون، خروج را تأیید می‌گیرد).

**رفتار (طبق توضیح شما):**
- هر آزمون ۱۵ سؤال چهارگزینه‌ای (`data-count`، قابل تغییر) و از هر سطح A1 تا C1 به‌طور مساوی (۱۵ ← ۳ تا از هر سطح؛ اگر تعداد بخش‌پذیر نباشد، باقی‌مانده از سطح‌های میانی اضافه می‌شود). سؤال‌ها از آسان به سخت چیده می‌شوند.
- هر سؤال: عنوان نوع آزمون، یک خط فارسی (دستور سؤال)، متن انگلیسی سؤال و چهار گزینه. شمارنده‌ی «پاسخ داده / مانده»، قبلی و بعدی، فهرست شماره‌ی سؤال‌ها و کلیدهای ۱ تا ۴ برای انتخاب گزینه.
- جواب درست **فقط بعد از پایان آزمون** در «مرور جواب‌ها» نشان داده می‌شود (فیلتر «همه / غلط»؛ در شنیداری متن صدا هم دیده می‌شود).
- بار اول نمره ندارد؛ بعد از هر آزمون آخرین نمره‌ی همان بخش روی کارتش می‌نشیند. آزمون نیمه‌کاره ذخیره می‌شود و «ادامه‌ی آزمون» دارد.
- شنیداری: پخش‌کننده با پخش/توقف، نوار پیشروی، **صدا و بی‌صدا** و **سرعت** (۰٫۷۵ تا ۱٫۵).
- سطح‌بندی ۵ سطحی: A1، A2، B1، B2، C1. سطح هر آزمون = بالاترین سطحی که پشت‌سرهم از A1 حداقل ۶۰٪ آن سؤال‌ها درست جواب داده شده (در `level-test.js`: `PASS`). **سطح کلی = میانگین سطح آخرین نتیجه‌ی آزمون‌های داده‌شده** (گرد می‌شود). هر المانی با `data-user-level` (در سایدبار دو جا گذاشته شده) خودکار به‌روز می‌شود.
- هرچه محاسبه‌ی فرانت است فقط نمایشی است؛ نمره و سطح رسمی را سرور دوباره حساب کند.

**🔌 بک‌اند** (کامل‌تر در `app/Support/PlacementTest.php` و بالای `level-test.js`):
1. **بانک سؤال** (بعداً از پنل ادمین): هر سؤال `{ id, section: vocab|grammar|listening, level: a1..c1, title, fa, q, options[4], answer(0..3), audio?, transcript?, explain? }`. دو راه تحویل: `data-start-url` (GET `?section=vocab` ← `{ questions: [...] }`) یا `data-bank` (همه‌ی بانک؛ دمو).

2. **پایان آزمون:** رویداد `placement:finish` (یا `data-finish-url` با POST + JSON + CSRF). `e.preventDefault()` یعنی «خودم ذخیره می‌کنم» و بعد `Teodel.placement.done(true, { overall: 'b1' })` یا `done(false)`.
   `payload = { section, answers:[{id, option}], correct, total, score, level, perLevel, overall, skills:{listening:'B1'} }`
3. **نمره‌های قبلی:** `$results` به صفحه داده می‌شود: `{ vocab: { score, level, correct, total, at }, … }` (کلید نباشد یعنی هنوز شرکت نکرده).
4. رویدادهای دیگر: `placement:start`، `placement:answer`، `placement:level` (سطح کلی تازه).
5. **صوت:** اگر `audio` باشد با `<audio>` پخش می‌شود. در دمو (بدون `audio`) متن `transcript` با صدای مرورگر خوانده می‌شود (صدا و سرعت دارد، نوار پیشروی ندارد؛ و روی دستگاه‌هایی که صدای انگلیسی ندارند پخش نمی‌شود).
6. **`LOCAL = true`** در `level-test.js`: نمره‌ها و آزمون نیمه‌کاره در localStorage می‌مانند. با اتصال بک‌اند `false` کنید.
7. ارتباط با «مهارت‌ها» در سایدبار: سطح شنیداری در payload (`skills.listening`) می‌آید؛ نمایش در کارت سایدبار با بک‌اند است.

## داشبورد (`/dashboard`) و تأیید خروج

**داده‌ها** (قرارداد کامل: `app/Support/Dashboard.php` → `demo()`؛ کنترلر: `DashboardController`):
`user{name,level,skills}`، `plan`، `streak{current,best,week[7]}`، `goal{minutes,today}`، `week[7 {at,minutes}]` + `week_prev_total`، `totals{songs_done,words_saved}`، `resume` (آخرین موزیک، مرحله از ۸، درصد)، `review{due,url}`، `recommended[3]`، `level_test{taken,total,url}`، `tickets{open,unread,url}`.

**رفتار** (`resources/js/modules/dashboard.js`): سلام بر اساس ساعت، پر شدن حلقه/نوار/نمودار با انیمیشن، شمارنده‌ها، تغییر هدف روزانه (۱۰/۲۰/۳۰/۴۵ دقیقه).
- ذخیره‌ی هدف: `data-goal-url` (POST، JSON `{minutes}` + CSRF). رویداد `dashboard:goal`.
- `LOCAL = true` فقط برای دمو (localStorage با کلید `teodel:dashboard:goal`)؛ هنگام وصل شدن بک‌اند خاموشش کنید.
- لینک «تهیه‌ی اشتراک» به `/subscription` می‌رود (صفحه‌اش هنوز ساخته نشده).
- در `Nav` آیتم داشبورد را به `/dashboard` وصل کنید.

**تأیید خروج**: `resources/js/modules/logout-confirm.js` همه‌ی فرم‌های `/logout` (تاپ‌بار، منوی «بیشتر» موبایل) را قبل از ارسال متوقف می‌کند و دیالوگ `partials/logout-dialog.blade.php` را نشان می‌دهد. «ماندن» = بستن بدون ارسال؛ «خروج» = ارسال فرم. دیالوگ از `bottom-nav` اینکلود می‌شود و به `@stack('modals')` در لایه نیاز دارد؛ اگر نبود، `confirm()` مرورگر جایگزین می‌شود.

## پیشرفت داینامیک (۰ تا ۱۰۰)

فرمول (در `app/Support/Progress.php` و `lesson.js`): **درصد = جمع پیشرفت هر مرحله (هر کدام ۰ تا ۱) ÷ ۸ × ۱۰۰**

- بک‌اند دو عدد می‌دهد: `completed_steps` و `current_step_fraction` (۰ تا ۱). درصد و وضعیت (`new/in_progress/done`) از آن‌ها ساخته می‌شود.
- **کارت لیست موزیک:** حلقه، درصد، ریبون، رنگ حاشیه و متن دکمه فقط به `data-status` و `data-progress` وابسته‌اند.
  برای تست در کنسول مرورگر: `Teodel.cards.set(2, 60)` (آهنگ شماره‌ی ۲ می‌شود ۶۰٪).
- تا وقتی بک‌اند وصل نشده، پیشرفتِ ثبت‌شده در صفحه‌ی آموزش در مرورگر ذخیره و در لیست نشان داده می‌شود
  (`LOCAL_PROGRESS` در `resources/js/modules/progress-sync.js`). وقتی بک‌اند وصل شد آن را `false` کنید.
- داخل هر مرحله، محتوا فقط این‌ها را صدا می‌زند:

```js
Teodel.lesson.setStepProgress(0.4); // ۴۰٪ از مرحله‌ی جاری انجام شد
Teodel.lesson.completeStep();       // مرحله‌ی جاری تمام شد
```

- رویدادها برای ذخیره‌سازی بک‌اند: `lesson:progress` و `lesson:step-complete` (داده: `{ song, step, fraction, percent, steps }`
  که `steps` پیشرفت هر ۸ مرحله است) و `lesson:step-change`.

## قرارداد داده (برای بک‌اند)

متغیرهای ویو `music.index`:

| متغیر | نوع |
|---|---|
| `$songs` | `LengthAwarePaginator` (۹ مورد در هر صفحه) |
| `$level` | `a` \| `b` \| `c` |
| `$filters` | `{ q, filter: all\|new\|in_progress\|done\|free, sort: default\|newest\|points\|duration\|title }` |
| `$subscribed` | bool |
| `$stats` | `{ completed, in_progress, points, highlights }` |
| `$user` | `{ name, days_left, points, level, skills: {listening, reading, writing, speaking} }` |

هر آیتم `$songs`:

```json
{
  "id": 1, "title": "Say My Name", "artist": "David Guetta", "cover": "https://…/cover.webp",
  "level": "a", "duration": "02:32", "points": 50,
  "completed_steps": 2, "current_step_fraction": 0.5,
  "is_free": true, "free_steps": 2, "total_steps": 8,
  "accent": "us", "year": 2022, "genre": "Pop", "wpm": 192, "topic": "Love", "album": "Album name"
}
```

- فیلدهای دیالوگ «اطلاعات موزیک»: `accent` (`us|uk|au|ie`)، `year`، `genre`، `wpm` (لغت در دقیقه)، `topic`، `album`. اگر خالی باشند «—» نشان داده می‌شود.
- `progress` (درصد) و `status` (`new` | `in_progress` | `done`) از `completed_steps` و `current_step_fraction` ساخته می‌شوند (`Progress.php`)؛ لازم نیست جدا بفرستید.
- `is_free`: یکی از ۳ آهنگ کاملاً رایگان. برای بقیه، کاربر رایگان فقط `free_steps` مرحله‌ی اول را می‌بیند.
- فیلتر، جستجو، مرتب‌سازی و صفحه‌بندی سمت سرور و با query string (`?level=&q=&filter=&sort=&page=`) است.
- «نمایش بیشتر» موبایل همان خروجی HTML صفحه‌ی بعد را با fetch می‌گیرد؛ API جدا لازم نیست.

## گزارش خرابی

`resources/js/modules/report.js` اسکرین‌شات بخش قابل‌مشاهده‌ی صفحه را می‌گیرد (html2canvas فقط هنگام کلیک لود می‌شود)
و payload زیر را می‌سازد. ارسال دو راه دارد:

1. رویداد: `$(document).on('report:submit', (e, payload) => {...})`
2. آدرس: مقدار `data-endpoint` روی `#report-form` در `partials/report-dialog.blade.php` (POST + JSON + CSRF)

```json
{ "description": "…", "screenshot": "data:image/jpeg;base64,… | null",
  "meta": { "url": "…", "locale": "fa", "userAgent": "…", "viewport": "390x844", "sentAt": "ISO-8601" } }
```

نکته: کاورها باید از همان دامنه یا با CORS درست سرو شوند، وگرنه در اسکرین‌شات خالی می‌افتند.

## حالت تمرکز

عناصری که `data-focus-hide` دارند در حالت تمرکز مخفی می‌شوند. انتخاب کاربر در `localStorage` (`teodel:focus`) می‌ماند.
در صفحات بعدی فقط `<x-page-tools />` را در هدر صفحه بگذارید و `data-focus-hide` را روی بخش‌های اضافی.

## وضعیت تست

PHP با `php -l` و JS با `node --check` بررسی شده. **بیلد Vite و نمایش در مرورگر انجام نشده** (در محیط ساخت، رجیستری npm در دسترس نبود)؛
پیش از استفاده یک بار `npm run build` و بازبینی چشمی در موبایل/دسکتاپ، هر دو زبان لازم است.
